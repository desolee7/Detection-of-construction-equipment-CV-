# Детекция строительной техники

Исследовательский проект по обнаружению строительной техники на изображениях. Репозиторий содержит ноутбуки для подготовки и объединения датасетов, экспериментов с YOLO-World и YOLOE, обучения YOLO26 и проверки экспортированной ONNX-модели.

## Возможности

- Преобразование аннотаций COCO, Pascal VOC и LabelMe; перевод полигонов в ограничивающие прямоугольники и подготовка разметки YOLO.
- Очистка датасетов, сопоставление классов из разных источников и сборка общего набора данных.
- Эксперименты с текстовыми запросами для YOLO-World и YOLOE, расчёт метрик и построение графиков.
- Обучение YOLO26 с подбором гиперпараметров через Optuna и записью экспериментов в MLflow.
- Экспорт обученных весов в ONNX и пробный инференс на изображениях.

## Классы техники

В `data_preproc/finale.ipynb` задан список из десяти целевых классов:

1. Экскаватор
2. Самосвал
3. Грузовой автомобиль
4. Кран
5. Фронтальный погрузчик
6. Автобетоносмеситель
7. Бульдозер
8. Прицеп
9. Каток
10. Автобетононасос

При использовании собственных данных проверьте соответствие идентификаторов классов и поля `names` в YAML-конфигурации датасета.

## Подготовка окружения

Основной код написан на Python. Для работы с ноутбуками нужен Jupyter; обучение может использовать NVIDIA GPU с CUDA. В основном пайплайне предусмотрен выбор CPU, если CUDA недоступна, но настройки отдельных ноутбуков нужно проверять отдельно.

Пример установки в Windows PowerShell из корня проекта:

```powershell
python -m venv venv
.\venv\Scripts\python.exe -m pip install --upgrade pip
.\venv\Scripts\python.exe -m pip install torch torchvision ultralytics optuna mlflow pandas numpy matplotlib opencv-python pillow pyyaml tqdm jupyter openpyxl datasets onnx onnxruntime onnxslim
.\venv\Scripts\python.exe -m jupyter lab
```

Это список основных зависимостей по импортам в коде, а не зафиксированное окружение: файл с проверенными версиями зависимостей пока отсутствует. Для обучения на GPU требуется сборка PyTorch, совместимая с установленными драйверами и CUDA. Отдельным экспериментам могут понадобиться дополнительные пакеты.

## Порядок работы

### 1. Подготовить данные

Датасеты и веса моделей не поставляются с исходным кодом. Разместите их локально и настройте пути в нужных ноутбуках. В коде встречаются абсолютные пути Windows от рабочей машины автора — их необходимо заменить перед запуском.

Используйте ноутбуки из `data_preproc/` для нужного формата разметки. В `finale.ipynb` проверьте `DATASETS_ROOT`, путь к итоговому набору, `CLASS_MAPPING` и `FINAL_CLASSES`. Перед запуском ячеек, которые изменяют или перемещают данные, сохраните копию исходного датасета.

Типичная структура итогового набора:

```text
dataset/
  data.yaml
  images/
    train/
    val/
  labels/
    train/
    val/
```

В `data.yaml` укажите пути к выборкам и список классов. Каждому изображению должен соответствовать текстовый файл разметки YOLO с тем же именем.

### 2. Запустить эксперименты или обучение

- Для YOLO-World откройте `Yolo-world/world.ipynb` или `experiments.ipynb`, настройте пути к данным, веса и текстовые запросы.
- Для YOLOE откройте `YoloE/YoloE_experiments.ipynb` и проверьте путь к модели и параметры эксперимента.
- Для обучения откройте `Yolo_26/pipeline.ipynb`, укажите `DATASET_DIR` и проверьте `MODEL_WEIGHTS`, `MAX_EPOCHS`, `N_TRIALS` и `DEVICE`.

В основном пайплайне исходно указаны `yolo26m.pt`, 20 эпох и 5 испытаний Optuna. Результаты обучения сохраняются в `runs_yolo26`, артефакты MLflow — в `mlruns`, состояние исследований и трекинга — в локальных базах данных. Пути результатов зависят от рабочей директории ядра Jupyter; проверьте `PROJECT_DIR` перед запуском.

### 3. Экспортировать модель в ONNX

В `Yolo_26/export_onnx.py` задайте `MODEL_PATH`, указывающий на обученный файл `.pt`, затем выполните:

```powershell
.\venv\Scripts\python.exe Yolo_26/export_onnx.py
```

Текущие параметры экспорта: размер изображения 768, динамические размеры входа, opset 17, без встроенного NMS.

### 4. Проверить ONNX-модель

В `Yolo_26/test_onnx.py` настройте `MODEL_PATH`, `IMAGE_DIR` и `OUTPUT_DIR`:

```powershell
.\venv\Scripts\python.exe Yolo_26/test_onnx.py
```

Скрипт обрабатывает первые пять найденных изображений, сохраняет изображения с детекциями и выводит число обнаруженных объектов. Это проверка инференса, а не полноценная оценка качества на тестовом наборе.

## Что хранится в Git

В репозиторий включаются исходники, ноутбуки, конфигурации и отчёты. Через `.gitignore` исключены виртуальное окружение, веса моделей, ONNX-файлы, архивы, локальные датасеты в папках `dataset` и `datasets`, результаты экспериментов и базы MLflow/Optuna. Исключённые файлы остаются на компьютере.

Веса и данные для воспроизведения экспериментов нужно передавать отдельно. При добавлении новых наборов в папки с другими именами дополните `.gitignore`. Перед публикацией также проверьте вывод ячеек ноутбуков: он сохраняется внутри `.ipynb` и может содержать большие изображения или локальные данные.
